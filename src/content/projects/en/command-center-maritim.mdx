This is a web command center application for the maritime industry that I build with a team at Solusi 247 since 2025. Operators watch many things at once and steer the ship from a single screen, with data that updates live.

Because this is office work, this page deliberately shows no screenshots, system names, or data of any kind. I only describe the technical approach.

## What was built

A web interface that combines a map, charts, indicators, and live video, in several display modes that match how operators work. My job is to make sure the data on screen matches its source and that the screen does not confuse the people using it.

## Challenges

Sensor data keeps changing. Work is often only half done when another sensor has already been installed on the ship and needs to be on screen quickly, so priorities shift before the first task is finished. The screens have to be easy to add or change without reworking what already exists.

The other challenge is the sheer amount of incoming data. I had to think about how to receive and display it without making the screen heavy, while keeping the architecture easy to change. When I am in the middle of something and the data a sensor returns changes, I have to adapt right away without breaking other parts.

## Technical decisions

Data arrives over WebSocket (Socket.IO) and is shown as charts with ECharts and a map with Leaflet. Components use OnPush change detection so a screen that changes often stays light.

One codebase serves several platform configurations, with a folder per capability and configuration per platform instead of a copy of the code for each platform. I am helping reshape the structure in that direction.

Core logic is tested with Vitest.
